migong_car5 速度环数值仿真报告 — 编码器取正后，误差定义必须翻回教科书式

1. 我如何做的模拟（方法）

纯 Python（标准库）闭环数值模型，完全照搬固件 PID 公式，并把之前漏掉的 编码器符号作为变量建模：

  • PID：复制 pid.c::Position_PID_Realize（位置式，积分限幅 ±5000）。
  • 三个符号量：闭环方向由它们的乘积决定 P = (encoder_sign) × (Kp符号) × (误差形式符号)， 其中 encoder_sign = -1 表示原固件 reality=-GetMotorPulse，+1 表示取正； 误差形式 = -1 表示 Bias=target-reality（教科书），+1 表示 reality-target。
  • 被控对象：关键修正——plant 增益符号随编码器符号翻转 drive = enc_sign × KPLANT × pwm。因为把 -GetMotorPulse 改成 +GetMotorPulse 本身就反转了"测得速度随 pwm 的反应方向"。 这正是上一版仿真漏掉的环节。
  • 调用关系：main() 死循环每 1ms 调 PID，编码器速度每 10ms（TIM4 中断）刷新； Set_PWM 注释明确"大于 0 正向转"，即 正 PWM = 前进。

参数为合理工程估值（满程 ~0.84 m/s，机械时间常数 0.25s），用于演示极性机理； PID 公式、误差定义、调用周期、以及"翻编码器会翻转 plant 增益"逐字对齐代码逻辑。

2. 仿真验证：三种配置的车速

下图为目标 1.0 m/s（接近满程）时的车速时域：

  • 红（original firmware）：enc-, Kp=-30, Bias=target-reality → 平稳收敛到 +0.846 m/s（前进）。这是已知可工作的基准。
  • 蓝（CURRENT CODE BUG）：enc+, Kp=+30, Bias=reality-target（上一轮留下的状态）→ 发散到 负值（倒退/自激）。证明"只翻编码器、不翻回误差定义"会把闭环方向反转。
  • 绿（FIX intuitive）：enc+, Kp=+30, Bias=target-reality（教科书式误差）→ 与红线同为正向收敛 +0.846，且 Kp 为正、编码器为正、误差为教科书式，符合直觉。

3. 为什么"翻编码器"必须同时"翻回误差定义"

闭环方向由 P = enc × Kp符号 × 误差形式符号 决定。原固件前进： (-1) × (-1) × (-1) = -1。

用户想要的"全正数直觉配置"：(+1) × (+1) × (-1) = -1 → 与原固件同向，前进。 这里 误差形式 = -1 即 Bias = target - reality（教科书）。

若只翻编码器而保留 Bias=reality-target（误差形式=+1）： (+1) × (+1) × (+1) = +1 → 与原固件反向，倒退。这就是上一轮留下的 bug。

下图（稳态车速 vs 目标）再次印证：红（original） 与 绿（FIX） 全程为正且重合， 蓝（CURRENT CODE BUG） 全程为负（倒跑/发散）。

5. 结论与代码修复

  • 根因（上一轮失误）：把编码器从 -GetMotorPulse 改成 +GetMotorPulse 是第三个符号翻转； 此前为了让 Kp 变正，已把 Kp 与 Bias 一起翻（两翻=净不变）。这次只翻了编码器、没把 Bias 翻回， 导致 P 从 -1 变 +1，闭环方向反转 → 车会倒着跑。仿真已铁证验证。
  • 正确修复（符合直觉）：
    • control.c TIM4 ISR：Uinttime_MotorPulse = GetMotorPulse(...) 取正（保留）。
    • pid.c：Position.Kp = 30, Ki = 2.6（正增益，保留）； Bias = target - reality;（翻回教科书式，之前错误地写成 reality-target）。
    这样 enc(+)×Kp(+) 与 target-reality 的乘积仍为 -1，与原固件同向，车前进，且参数全部符合直觉。
  • 说明：仿真中 plant 增益符号随 enc 翻转，是对"翻编码器"这一步的忠实建模； 绝对 PWM→运动的极性由硬件决定、代码无法看出，但相对原固件的符号乘积已严格证明上述结论。
