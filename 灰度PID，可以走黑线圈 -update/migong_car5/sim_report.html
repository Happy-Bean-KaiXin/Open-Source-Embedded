migong_car5 速度环数值仿真报告

1. 我如何做的模拟（方法）

没有烧录、没有上电，用纯 Python（标准库）搭了一个闭环数值模型，完全照搬固件逻辑：

  • PID：复制 pid.c::Position_PID_Realize 的位置式 PID（比例+积分，积分限幅 ±5000），当前增益 Kp=-30, Ki=-2.6（负值）。
  • 调用关系：固件在 main() 死循环里每轮调 PID，而编码器速度只在 TIM4 10ms 中断里刷新。模拟两种模式： current = 每 1ms 调一次 PID、但速度反馈值在 10ms 内不更新（同一误差被反复积分，等效积分增益放大约 10 倍）； fixed = PID 每 10ms 调一次、与编码器刷新对齐。
  • 极性对照：额外加一个 fix#5 场景——把 Kp/Ki 翻成正——用来检验"翻符号能否修 bug"。仿真显示它让车倒着跑，从而证明极性绝不能盲翻。
  • 被控对象：电机+轮子用一阶惯性 r → -KPLANT·pwm（KPLANT=0.0156, TAU=0.25s）。板子上"电机接反 + 编码器取负"两个符号翻转恰好抵消，喂给 PID 的速度就是正的（前进为正），这正是"车能低速前进、但极性是错配凑成"的现实。
  • 目标速度：按固件公式 TarEncodeSpd = TarSpeed×1560/(0.1885×100) 换算成"脉冲/10ms"，与反馈同单位。

参数为合理工程估值（电机满程 ~0.84m/s，机械时间常数 0.25s），用于演示机理，不代表逐毫秒精确；但调用周期与极性结构是逐字对齐代码的。

2. 仿真验证：极性不能盲翻 + 当前环可稳定达速

下图是目标速度 1.0 m/s（接近满程）时的车速时域。红/绿（current / fix#1） 平稳收敛到目标速度（0.846 为满程饱和值），说明在合理工程模型下，当前负增益环路本身能正常工作、低速/中速不抖。关键看 蓝（fix#5：把 Kp/Ki 翻成正） —— 它直接收敛到 -0.846 m/s，即整车倒着跑。这用仿真铁证说明：速度环增益符号绝不能盲翻，当前负值是与板子极性（电机接反 + 编码器取负）将错就错凑成的，翻正就倒退。

3. 为什么仿真里没复现"高速抖"？真实根因在哪

上表三种配置稳态抖动都 ≈0，因为本模型是一阶 + 小延迟的理想简化。真实小车的抖动来自这个模型没包含的更高阶 / 耦合因素，而这些恰恰对应前面审出的代码 bug：

  • #1 调用周期抖动：固件在 main() 死循环里调 PID，循环周期被 OLED(I2C)、多路 ADC 等拖得忽长忽短，导致离散积分的"步长"时变、等效增益不稳；高速（误差大、积分大）时最易激发振荡。修复 = 把 PID 搬进 TIM4 的 10ms 中断，固定步长。
  • #4 编码器左右抄反（疑似）：左轮速度环读 Motor2、右轮读 Motor1，两轮速度环互控，高速差速 / 转向时错误被放大 → 抖 / 跑偏。修复 = 对照原理图确认后把 125/126 行对调，并用宏锁定。
  • 转向环 / 速度环强耦合：pwml=-turnpwm+spd, pwmr=+turnpwm+spd，直道也有微小纠偏，差速车高速时航向更敏感。

因此真正的修复是 #1 + #4 + 锁定 #5 极性，而非翻转增益符号。下图（稳态车速 vs 目标）再次印证：保留负增益可正达目标，翻正则倒跑。

5. 结论与代码修复对应

  • 仿真核心结论：用固件同款 PID 逻辑建模，当前负增益环路能正确达到目标速度；把 Kp/Ki 翻成正会让车倒着跑（速度变负）。故 #5 的正确处理是保留符号 + 加注释锁定极性约定，绝不能盲翻。
  • 修复 #1（关键）：速度环 PID 移入 TIM4 的 10ms 中断（或 main 里 10ms 节拍门控），固定积分步长，消除调用周期抖动引发的增益不稳。
  • 修复 #2：GetParament 中 SPAN 标定先用旧 Max 计算再更新，恢复峰值偏差语义。
  • 修复 #3：里程计算改为浮点，消除整圈跳变。
  • 处理 #4：TraceMove 左右编码器对调加宏 MOTOR_LEFT_IS_MOTOR1 + 注释，对照原理图确认后切换，避免盲改把能跑的车搞乱。
