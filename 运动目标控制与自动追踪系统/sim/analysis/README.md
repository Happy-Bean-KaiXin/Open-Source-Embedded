# sim/analysis 文件夹说明文档

> **这份文档干嘛的**:`sim/analysis/` 是 `User/contorl/contorl.c` 里 DDA 直线生成器(双轴舵机沿直线运动)的离线仿真与误差分析目录。
> 里面用 Python **逐行复刻**固件的 float32 算术和截断行为,然后跑大样本线段,回答一个核心问题:
> **按规则 `|dx|>=|dy| → 驱动 X 轴` 选驱动轴,终点误差到底有多大?错选轴又会炸到什么程度?**

---

## 0. 30 秒看懂整个目录

**一句话类比**:
- 固件像一个小机器人,沿直线推激光笔,每步只能走 7 像素,走到目标附近 4 像素就算"到了"停下来。
- 直线有横有竖,机器人需要决定**沿 X 走还是沿 Y 走**(选大跨度的轴当驱动轴)。
- 这个目录做了三件事:
  1. **复刻**固件的算术(把机器人在 Python 里重造一个)。
  2. **跑实验**——造 172+ 条线段(横、竖、斜、随机),让它走。
  3. **出图出表**——把每条线的"实际停点"和"目标点"距离画出来,证明"按规则选轴"误差小(最多 5px ≈ 14mm),"选错轴"误差爆炸(可超 160px ≈ 450mm)。

## 1. 关键固件参数(所有脚本共用)

| 参数 | 值 | 物理含义 | 出现在 |
|------|------|----------|--------|
| `STEP` | **7 px** | 每步走多远 ≈ 20 mm | contorl.c 主循环 |
| `DEADZONE` | **4 px** | 离目标多近算"到了" ≈ 11 mm | contorl.c:696/724/758 |
| `PX_PER_M` | 352 px/m | 1 px ≈ 2.84 mm | 物理换算 |
| **选轴规则** | `|dx|>=|dy| → X 驱动` | 驱动大轴(跨度大的那个) | 各 `*_Y_*` 分支 |
| **终止条件** | 驱动轴进入目标 ±DEADZONE 即停 | 死区提前停 | 全部脚本 |

**4 个固件函数**(每个 Python 脚本都复刻,逐行对应):
- `calcSlope(x1,y1,x2,y2)` → 斜率,dx=0 返回 0.0
- `calcInt(x1,y1,slope)` → 截距,`slope=0` 时返回 0
- `calcY(x,slope,intercept)` → 已知 x 推 y(X 驱动时用)
- `calcX(y,slope,intercept)` → 已知 y 推 x(Y 驱动时用,`slope=0` 时返回 0)

**复刻算术的两把钥匙**:
```python
def f32(x):   return struct.unpack("f", struct.pack("f", float(x)))[0]  # 模拟 C float 单精度
def trunc(x): return int(x)                                                # 模拟 C (int) 向零截断
```

## 4. 脚本详解(做什么 / 怎么用 / 产出啥)

### 4.0 `analysis_utils.py` —— 公共绘图工具(所有脚本共用)

- **做什么**:统一解决两个历史痛点:
  1. **豆腐块**:中文字体自动探测 + 全局注册(fallback 链 `Microsoft YaHei → SimHei → DejaVu Sans`)。**关键修复**:SimHei 缺 U+2212(数学负号 −)字形,会把 log 轴刻度 `10⁻¹` 的负号渲染成方块;改用雅黑优先 + DejaVu 兜底后彻底消失
  2. **文字重叠/溢出**:解释区自动按 CJK 宽度换行 + 自动行高,行数再多也不重叠
- **提供的函数**:
  | 函数 | 作用 |
  |------|------|
  | `setup_chinese_font()` | 注册中文字体并写入 rcParams,返回 FontProperties |
  | `add_banner(fig, title, purpose)` | 图顶部画"本图目的"横幅(蓝色圆角框) |
  | `add_explanation(fig, lines, y0, h, ...)` | 图底部画解释区(自动换行,`(文本, 是否粗体)` 元组列表) |
  | `wrap_cjk(text, width)` | 按显示宽度换行(中文=2 宽,西文=1 宽) |
  | `add_footer(fig, script)` | 图底部加"脚本来源"小水印 |
- **为什么必须用它**:5 个脚本原本各自硬编码 `C:\Windows\Fonts\simhei.ttf`,字体缓存未注册时全图豆腐块;现在统一走 fallback 链,换机器也不会缺字。

### 4.1 `gen_large_figs.py` —— 大样本主实验

- **做什么**:造 **12 条手工** + **160 条随机**(种子 20260817)共 **172 条**线段,每条都跑两遍("按规则选轴"和"故意错选"),记录:
  - 终点的欧氏距离误差(`endpoint_err`)
  - 轨迹上每点到理想直线的垂距(`perp`)
- **数据集构成**:纯横、纯竖、正对角、反对角、四个象限、ratio 从 0.03 到 1e6
- **产出**:
  - `large_test_dataset.csv`(15 列,12.6 KB)
  - `fig1_perstep_dev.png` — 每步垂距
  - `fig2_endpoint_err.png` — 终点误差对比(本目录的**核心证据图**)
  - `fig3_examples.png` — 浅/陡线轨迹叠加
  - `fig4_feasibility_basis.png` — 误差极值柱状图
- **关键数字**(脚本自身打印):
  - 规则终点误差 max ≈ 5.0 px,avg ≈ 2.05 px
  - 错选终点误差 max ≈ 162 px(30+ 倍膨胀)
  - 每步垂距 max ≈ 1.89 px
- **怎么用**:`python gen_large_figs.py`

### 4.2 `gen_moderate_case.py` —— 中等差异区间

- **做什么**:聚焦 **ratio = 0.1 ~ 10** 这段"中等斜率"区间(规则选轴和错选差距不那么大),做三件事:
  1. 加入**理想状态线**(纯 double 浮点、只受死区约束)作为理论下限
  2. 画扫描曲线(ratio 连续变化)
  3. 用超大下文字框**逐元素解释图表**(X/Y 轴、三条线、每个标注)
- **产出**:`fig5_moderate_case.png`(单图但很详细,自带完整说明)
- **关键结论**:
  - ratio < 0.3 或 > 3:差距巨大(可达 30px+),必须按规则
  - 0.3 ~ 3:差距微小(0~4px),规则仍略优
  - ratio = 1(对角):两线完全重合,选谁都一样

### 4.3 `gen_schematic.py` —— 空间示意图

- **做什么**:挑一条经典线段 `S(100,100)→E(160,140)`(dx=60,dy=40,ratio=1.5),画:
  - 主图:理想直线 + 实际阶梯路径 + 起点/目标/停点
  - 放大窗:停点 P' 与目标 E 的微小偏差
  - 误差箭头 + 文字标注
- **产出**:`fig6_schematic.png`
- **特点**:最适合给非技术人员看,直观解释"误差是什么、误差多大、能不能接受"
- **典型输出**:err ≈ 3.16 px(≈ 9 mm)

### 4.4 `gen_xy_compare.py` —— X 算 Y vs Y 算 X 对比

- **做什么**:对每条线段**同时跑两种策略**(驱动 X、驱动 Y),把两种终点误差画成**配对散点**
- **产出**:`fig7_xy_compare.png`
- **关键观察**(直观图):
  - ratio > 1 时:**蓝点低、橙点高** → 驱动 X 更好
  - ratio < 1 时:**橙点低、蓝点高** → 驱动 Y 更好
  - ratio = 1 时:两点**重合** → 驱动谁一样
- **意义**:这条图是"为什么要按规则选轴"的视觉证明——规则本质上就是"在两种方法里选误差更小的那个"

### 4.5 `gen_error_analysis.py` —— 理论界 vs 实测

- **做什么**:在 **200 条随机线段**(种子 20260818)上叠加**两条理论曲线**:
  - 规则上界:`DEADZONE × √2 ≈ 5.66 px`(**常数**!)
  - 错选上界:`4 × max(ratio, 1/ratio)`(随 ratio 爆炸)
- **产出**:`fig8_error_analysis.png`
- **关键价值**:**用理论预测值验证实测**,证明规则误差有界得证(实测蓝点全压在 5.7px 线下方)

### 4.6 `sim_firmware_consistency_check.py` —— 一致性实证

- **做什么**(最特殊的一个):**不是仿真,是审计**。对比三组实现:
  - A. 固件忠实版(`fw_*`,严格按 C 语义,带 int 隐式截断)
  - B. Python 仿真版(`py_*`,照搬其他脚本的算术)
  - C. JS 仿真版(`Motion_TarCtrl_Sim.js`,跑一遍抓末点)
- **跑多少**:5000 条随机线段
- **判定标准**:同一组输入下,`slope / intercept / calcY / calcX` 逐位对比,差 ≤ 1e-6 算一致
- **产出**:控制台报告
- **意义**:**证明仿真代码就是固件代码的忠实副本**,所有 fig 数字能直接当固件性能参考
- **附带**:还会调 `../sim_code/Motion_TarCtrl_Sim.js` 自测一遍,把输出也打出来

## 5. 8 张图详解(对照查阅用)

### 图 1 — `fig1_perstep_dev.png`「每步垂距」

- **图内容**:172 条线段每条轨迹上"最远离理想直线的一步"的距离,按 `ratio = |dx|/|dy|` 横轴铺开
- **蓝点**:规则驱动 X 轴,橙点:规则驱动 Y 轴
- **怎么读**:X 对数轴 10⁻² ~ 10⁶,垂距全在 0 ~ 1.9 px 之间
- **结论**:每步落点相对理想直线偏差 ≤ 2px,平均 < 1px,说明"从轴每步重算"让轨迹始终贴着直线走

### 图 2 — `fig2_endpoint_err.png`「终点误差对比(核心图)」

- **图内容**:同一组线段,蓝点 = 按规则选轴,橙点 = 故意错选,横纵都 log
- **关键模式**:
  - 蓝点**始终压在底部**(大部分 1~5px)
  - 橙点在 ratio 极端处**爆炸式上升**(可达 150+ px)
  - ratio=1 处两群重合(对角线对称)
- **结论**:规则选轴在全部区间都是最优或至少不劣;极端斜率处错轴代价巨大,必须按规则
- **重要程度**:⭐⭐⭐ 这是写报告/答辩最值得拿出来的一张

### 图 3 — `fig3_examples.png`「浅线/陡线轨迹叠加」

- **图内容**:左=浅线(dx=120,dy=30),右=陡线(dx=30,dy=120)
- **每幅子图**:
  - 绿线=理想直线
  - 蓝色阶梯=规则驱动路径
  - 橙色阶梯=错选轴路径
  - 黑圆=起点 S,红星=目标 E
- **怎么读**:
  - 浅线:蓝紧贴绿,橙大幅偏离
  - 陡线:蓝紧贴绿,橙大幅偏离
- **结论**:直观证明"错选轴"为什么会炸——小跨度轴当驱动轴,从轴被斜率放大

### 图 4 — `fig4_feasibility_basis.png`「误差上界汇总」

- **图内容**:4 根柱子
  - 规则终点误差 max = **5.00 px**(约 14 mm)
  - 规则终点误差 avg = **2.05 px**
  - 错选终点误差 max = **162.00 px**(约 460 mm)
  - 每步最大垂距 = **1.89 px**(约 5.4 mm)
- **结论**:一图看完"规则 vs 错选"的代价差,数量级 30+ 倍

### 图 5 — `fig5_moderate_case.png`「中等差异区间」

- **图内容**:上半部分是曲线,下半部分是大段文字逐元素解释
- **三条线**:
  - 蓝实线:固件按规则
  - 橙虚线:固件反着选
  - 绿点划线:**理想状态理论下限**(纯浮点、只受死区约束)
- **关键发现**:绿线和蓝线几乎重合 → 整数截断带来的误差其实只多 0~1px,**主要误差来源是死区机制本身**,不是截断
- **特殊价值**:自带详细的"图怎么读"说明文档,适合新人入门

### 图 6 — `fig6_schematic.png`「单条线段空间示意图」

- **图内容**:画一条具体线段 S(100,100)→E(160,140)
- **元素**:
  - 绿直线=理想路径
  - 蓝阶梯=固件每步 +7px 落点
  - 黑圆=起点,红星=目标,橙菱形=实际停点 P'
  - 红色双向箭头=P' 到 E 的距离
  - 右下角放大窗:P' 与 E 的细节偏差
- **怎么读**:err = 3.16 px ≈ 9 mm(对 0.5m 矩形标定区可忽略)
- **结论**:把"误差"这个抽象概念用一张图讲清楚,最适合解释给非技术人员

### 图 7 — `fig7_xy_compare.png`「X 算 Y vs Y 算 X 对比」

- **图内容**:80 条线段(6 手工 + 74 随机),每条同时跑"驱动 X"和"驱动 Y",画配对散点
- **关键观察**:
  - ratio > 1:**蓝低橙高** → 驱动 X 更好
  - ratio < 1:**橙低蓝高** → 驱动 Y 更好
  - ratio = 1:两点重合
- **结论**:规则 `|dx|>=|dy| → X 驱动` 就是在两种方法里**自动选误差更小**的那个,这是数学最优而非经验法则

### 图 8 — `fig8_error_analysis.png`「理论界 vs 实测」

- **图内容**:200 条随机线段(蓝=规则实测,橙=错选实测) + 两条理论曲线
- **两条理论线**:
  - 蓝色横线 = 规则上界 `4 × √2 ≈ 5.66 px`(常数!因为有效斜率 ≤ 1)
  - 橙色 V 形线 = 错选上界 `4 × max(ratio, 1/ratio)`
- **怎么读**:
  - 蓝实测点全压在蓝线下方 → 规则误差有界得证
  - 橙实测点跟随橙线 → 错选代价可由理论精确预测
- **结论**:实测和理论吻合,反过来**给 firmware_error_proof.md 的数学证明提供了实证背书**
