2023电赛--运动目标控制系统

说明文档（修复记录与原因）

一、系统概述
本系统为 2023 全国大学生电子设计竞赛 E 题"运动目标控制与自动追踪系统"的
开源实现，硬件平台为 STM32F103 + OpenMV 视觉模块 + 两轴舵机云台 + OLED + 4 键。
固件在 User/contorl/contorl.c 中实现两个核心运动控制函数：
  - Motion_TarCtrl        ：控制激光追踪"红大方框/标定矩形"（步长 7）。
  - Motion_TarCtrl_Black  ：控制激光巡线"A4 黑胶带框"（步长 1）。
OpenMV 在 mv/openmv/main.py 中完成矩形识别与角点提取。
对应仿真见 sim/motion_sim.html（含 Motion_TarCtrl_Sim / Motion_TarCtrl_Black_Sim，
与固件同名函数一一对应，便于逐行比对）。

二、本次修复的 Bug 及其原因（为什么要修复）

BUG1：OpenMV 矩形识别 ROI 被硬编码（视觉层）
  - 原实现：find_rect 使用固定 ROI = (44,35,240,191)，只在图像固定区域搜索矩形。
  - 后果：A4 靶纸必须贴在屏幕固定位置才能被识别，贴偏即识别失败或丢帧。
  - 为什么要修：赛题要求 A4 靶纸可贴在屏幕任意位置（赛题(3)(4)）。固定 ROI 直接
    违背赛题，且实机安装误差下极易漏检。
  - 修复：改为全幅搜索 img.find_rects(...)，并用 is_a4_target() 按 A4 长宽比
    （约 1.414，容差 ±0.18）与面积占比（<55%）过滤，排除屏幕边框等误检。

BUG2：黑框运动错借红框标定中心（控制层，严重）
  - 原实现：Motion_TarCtrl_Black 中黑框巡线的起点与吸附目标，误用了红大方框的
    标定中心 bx_center / by_center，而非黑框自身几何中心。
  - 后果：激光沿错误的几何中心运动，全程偏离黑胶带，巡线/追踪失败。
  - 为什么要修：红大方框与 A4 黑框是两个独立目标、位置不同，参数相互耦合是
    复制粘贴遗留问题；黑框必须以自身四角算出的质心作为控制基准。
  - 修复：黑框起点取自身四角质心 bx_c / by_c（Centy_To_Start 段），并按四角顺序
    corner0→1→2→3→0 顺时针巡线。

BUG3：黑框中心起步穿越纸内脱胶（评分风险，备选规避）
  - 原现象：默认从 A4 纸内"中心"起步（Centy_To_Start）。"中心→角点"这一段要
    穿过纸内部，约 13.6cm 处于黑胶带之外（在白纸上）。
  - 后果：若评分规则含"连续脱离胶带 5cm 记 0 分"，该段可能被判定为脱离而扣分。
  - 为什么要修：主流程按赛题"取 A4 自身中心"作为起步点，但起步段确实不在胶带上，
    存在评委异议的风险，需给出规避手段。
  - 修复 / 规避：新增宏 BLACK_FRAME_START_FROM_CORNER（定义在 contorl.h）：
        = 0 主流程：从 A4 自身中心起步（Centy_To_Start），符合赛题"取中心"表述；
        = 1 备选方案：从胶带角点起步，corner0→1→2→3→0 顺时针巡线，全程贴胶带，
                      物理上不存在脱胶段（仿真验证 maxOff = 0）。
    该宏仅切换起步方式，巡线几何逻辑完全一致，作为"一键规避"备选。

配套修正 A：x/y 坐标数组赋值镜像 bug（修复过程中发现）
  - 原实现：黑框状态机中，X 坐标数组 Black_Retanx 被错赋给 Flag.y_actual，Y 坐标
    数组 Black_Retany 被错赋给 Flag.x_actual，等效于把目标点沿 y=x 镜像翻转。
  - 为什么要修：导致激光追踪到镜像后的错误位置，巡线必然偏离。
  - 修复：改为 X→x_actual、Y→y_actual（即 Flag.x_actual = Black_Retanx[...];
    Flag.y_actual = Black_Retany[...]）。

配套修正 B：工程内错误注释
  - 原现象：多处写成 "Flag.x_actual = bx_c; // 让实际值y 等于 y 的中心坐标"，
    注释与代码实际作用相反（应为"让实际值 x 等于 x 的中心坐标"）。
  - 为什么要修：误导性注释会在后续维护中诱发上述 x/y 类 bug。
  - 修复：将 6 处错误注释更正为与代码一致的"让实际值 x / y"。

辅助改动：PX_PER_M 标定为宏
  - 像素/米标定系数固化为 #define PX_PER_M 352.0f（176px ≈ 0.5m），定义在
    contorl.h。仿真侧使用同一常量，保证仿真与真机建模一致。

三、仿真与固件一致性验证
  - 仿真已抽取 Motion_TarCtrl_Sim / Motion_TarCtrl_Black_Sim 与固件同名函数一一对应

五、运动控制原理（通俗版）
本系统的激光要沿着矩形四条边走一圈。但舵机每 10ms 只能“跳”一个固定步长
（7 像素），而且每次只能沿一个轴（x 或 y）前进，另一个轴用直线方程算出来。
整个走线靠两个朴素思想：

1. 沿“长边”走（主轴驱动，代码里的 |dx|>|dy| 判断）
   好比在方格纸上画线，但笔只能沿一个方向跳：线偏横就沿 x 跳、偏竖就沿 y 跳。
   选“变化大的那个轴”当自变量，每一步沿直线走的距离才≈步长，均匀不突跳；
   若选变化小的轴，每一步会沿直线蹦出一大截（被斜率放大）。完全竖直时 dx=0、
   斜率无穷大，绝不能“沿 x 走、算 y”，所以竖边必须沿 y 走（代码 if(dx!=0) 守卫）。

2. 够近就停（到达死区，代码里的 <4 判定）
   激光永远无法正好落在目标角点上（离散跳步会跨过它），所以改成“离目标不到
   4 像素就算到”。关键是 4 必须大于步长的一半（7/2=3.5）：否则一跳就可能整步
   跨过目标、永远不触发。到达后再把位置“吸附”到精确角点，避免多段误差累积漂移。

一句话总结：选主轴 → 按步长跳着走 → 进死区就停并吸附 → 走下一段。
